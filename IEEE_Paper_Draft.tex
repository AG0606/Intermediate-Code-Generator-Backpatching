% ABSTRACT
% ============================================================
\begin{abstract}
Conventional compiler front-ends construct a heap-allocated Abstract Syntax Tree~(AST) before lowering source programs into intermediate representations, incurring memory and latency overheads that modern streaming and just-in-time architectures seek to avoid. We present a single-pass Intermediate Code Generator~(ICG) for a substantial subset of ANSI~C that extends the classical backpatching technique with four contributions: (i)~a hierarchical scope stack with on-the-fly identifier mangling that resolves nested variable shadowing directly in the Three-Address Code~(3AC) stream without an AST; (ii)~a dual-marker synchronisation pattern that reconciles the grammatical--execution order mismatch of C \texttt{for} loops in $O(1)$ auxiliary space; (iii)~an automated leader-based partitioner that constructs a Control Flow Graph~(CFG) with semantically typed edges (True, False, Jump, Fallthrough) from the raw quadruple array; and (iv)~a coupled four-pass optimiser with an in-place address-remapping vector that guarantees branch-target integrity after dead-code elimination. The system is implemented in approximately 2\,500~lines of ANSI~C with Flex~2.6 and Bison~3.8, and passes all~14 end-to-end test suites covering branching, loops, \texttt{switch-case}, short-circuit Boolean logic, scoped declarations, semantic and syntactic error recovery, and multi-pass optimisation.
\end{abstract}

\begin{IEEEkeywords}
intermediate code generation, backpatching, three-address code, control flow graph, syntax-directed translation, single-pass compilation, dead-code elimination, variable shadowing
\end{IEEEkeywords}

% I.  INTRODUCTION
% ============================================================
\section{Introduction}

Intermediate code generation is the compiler phase that lowers a parsed source program into a machine-independent representation suitable for optimisation and eventual target-code emission. Production compilers such as LLVM/Clang~\cite{llvm} and GCC accomplish this through multi-pass pipelines: the front-end first constructs a persistent Abstract Syntax Tree~(AST), performs semantic analysis and type checking over repeated traversals, and finally lowers the annotated tree into a linear intermediate representation~(IR) such as LLVM-IR or GIMPLE~\cite{dragonbook,llvm}.

Although multi-pass AST-based architectures enable powerful whole-program transformations, their heap-allocated tree nodes incur non-trivial memory pressure and cache-miss penalties. These costs are especially problematic in \emph{streaming compilation} scenarios---exemplified by the WebAssembly standard~\cite{wasmhaas} and the Liftoff baseline compiler in Google's V8 engine~\cite{v8liftoff}---where machine code must be emitted with minimal latency as bytecode arrives over the network. In such environments, even a single full-tree traversal may be prohibitively expensive.

An alternative paradigm is \emph{single-pass syntax-directed translation}~(SDT), in which intermediate instructions are emitted directly during parsing. However, SDT introduces the well-known \emph{forward-jump dilemma}: when the parser encounters a conditional branch such as
\begin{lstlisting}
if (a < b) { x = 1; } else { x = 2; }
\end{lstlisting}
the jump destination of the false branch is unknown because the \texttt{then}-block has not yet been parsed. The textbook solution, \emph{backpatching}~\cite{dragonbook}, maintains linked lists of incomplete jump instructions whose targets are filled in (``patched'') once the destination quad becomes known. Despite its elegance, the original formulation addresses only flat grammars with trivial control flow and a single global namespace.

Extending backpatching to handle a realistic C subset raises four engineering challenges that motivate this work:
\begin{enumerate}[leftmargin=*]
\item \textbf{Lexical scoping.} C permits variable re-declaration inside nested blocks. A flat symbol table cannot distinguish inner and outer instances of the same identifier during single-pass emission, leading to corrupted variable references.
\item \textbf{For-loop order inversion.} In~C, the grammatical token order of a \texttt{for} header is \emph{init--condition--step}, but the execution order is \emph{init--condition--body--step}. A bottom-up LALR(1) parser~\cite{deremer1982} processes tokens left-to-right, so the step expression is parsed \emph{before} the body that must precede it at run time.
\item \textbf{CFG construction.} Textbook backpatching produces an unlabelled quadruple array with raw numerical jump targets but no structured control-flow graph amenable to further analysis.
\item \textbf{Post-backpatching optimisation.} Removing dead instructions shifts quadruple indices, silently corrupting all existing jump targets---a vulnerability recently termed ``branch-target corruption''~\cite{xdead}.
\end{enumerate}

\subsection{Contributions}
We address each challenge through a distinct algorithmic mechanism:
\begin{itemize}[leftmargin=*]
\item A \emph{hierarchical scope stack} with dynamic identifier mangling (\S\ref{sec:scoping}) that isolates shadowed variables without an AST.
\item A \emph{dual-marker synchronisation pattern} (\S\ref{sec:forloop}) using two $\varepsilon$-non-terminals, $N_{\mathrm{skip}}$ and $N_{\mathrm{back}}$, that bridges the parse--execution order gap in $O(1)$ auxiliary space.
\item A \emph{leader-based CFG synthesiser} (\S\ref{sec:cfg}) that partitions quadruples into basic blocks with flow-typed edges.
\item A \emph{four-pass optimiser} (\S\ref{sec:opt}) with an address-remapping vector that maintains branch-target integrity.
\end{itemize}
The complete implementation, test suite, and build infrastructure are publicly available.\footnote{\url{https://github.com/AG0606/Intermediate-Code-Generator-Backpatching}}

% II.  RELATED WORK
% ============================================================
\section{Related Work}

\textbf{Classical backpatching.} Aho, Sethi, and Ullman~\cite{dragonbook} introduced the \textsc{makelist}--\textsc{merge}--\textsc{backpatch} algebra for resolving forward jumps in a single bottom-up pass. Their treatment covers simple \texttt{if-else} and \texttt{while} constructs but omits block scoping, \texttt{for}-loop reordering, \texttt{switch-case} dispatch, and post-generation optimisation. Levine et al.~\cite{lexyacc} provided practical guidance for building Flex/Bison parsers using LALR(1) grammars~\cite{deremer1982} but did not address intermediate code generation or backpatching.

\textbf{Streaming and single-pass compilation.} Google's V8 Liftoff compiler~\cite{v8liftoff} demonstrates the practical value of single-pass code emission for WebAssembly~\cite{wasmhaas}, using fixup tables---structurally analogous to backpatching---to eliminate the need for AST construction. Liftoff achieves sub-millisecond time-to-first-instruction on constrained devices. Similarly, the Lua programming language pioneered single-pass register-based bytecode generation without an AST~\cite{luaieru}. Our work generalises these streaming principles to source-level C control constructs with full lexical scoping.

\textbf{Multi-level and linear IRs.} Lattner et al.~\cite{mlir} showed with MLIR that basic blocks of linear operations remain the most effective abstraction for compiler transformations, building upon lessons from the LLVM compiler framework~\cite{llvm} and advocating explicit control-flow-graph representations over nested AST structures. Our CFG engine produces exactly this kind of basic-block representation from raw quadruples.

\textbf{Flow-typed edges and control flow analysis.} Niu et al.~\cite{fair} introduced the FAIR intermediate representation for static vulnerability detection, arguing that CFG edges must carry explicit semantic types (True, False, Jump, Fallthrough) to support sound analysis, extending Frances Allen's foundational control flow analysis techniques~\cite{allen1970}. Standard textbook backpatching outputs unclassified numerical targets; our system directly incorporates FAIR's edge classification taxonomy.

\textbf{Direct IR construction and SSA form.} Braun et al.~\cite{braun2022} proved that Static Single Assignment (SSA) form can be constructed directly during parsing without iterative dominator-tree computation over an AST, following earlier foundational work by Cytron et al.~\cite{cytron1991}. Our dynamic variable-mangling mechanism applies a similar principle in a bottom-up LALR(1) environment.

\textbf{Branch-target integrity and dead-code elimination.} Recent work on dead-code elimination in compiled binaries by Slind~\cite{xdead} highlights that deleting instructions without re-indexing jump targets introduces silent control-flow corruption. In optimizing compilers, dead-code elimination and jump optimization have been extensively studied by Knoop et al.~\cite{knoop1994} and Muchnick~\cite{muchnick}. Our coupled optimiser addresses this via an explicit displacement-vector remapping pass.

\section{Background and Notation}
\label{sec:background}

\subsection{Quadruple Representation}
The intermediate code is a linearly indexed array of four-tuples:
\begin{equation}
\label{eq:quad}
q_i = (\mathit{op},\; \mathit{arg}_1,\; \mathit{arg}_2,\; \mathit{result})
\end{equation}
where $\mathit{op}$ is an operator drawn from $\{$\texttt{=}, \texttt{+}, \texttt{-}, \texttt{*}, \texttt{/}, \texttt{\%}, \texttt{if}, \texttt{goto}, \texttt{param}, \texttt{call}, \texttt{return}, \texttt{func\_begin}, \texttt{func\_end}, \texttt{end}$\}$, $\mathit{arg}_1$ and $\mathit{arg}_2$ are operands (names, constants, or the placeholder ``$-$''), and $\mathit{result}$ is either an assignment target or a jump destination index. A global counter $\mathit{nextquad} \in \mathbb{N}_0$ tracks the next available slot. The array is pre-allocated to 10\,000~entries, sufficient for the programs in our target domain.

\subsection{Backpatching Algebra}
Let $\mathcal{L}$ denote a list of quadruple indices whose jump targets are unresolved. Three primitives govern backpatching:
\begin{align}
\textsc{makelist}(i) &\;\to\; \{i\} \label{eq:makelist}\\[2pt]
\textsc{merge}(L_1,L_2) &\;\to\; L_1 \cup L_2 \label{eq:merge}\\[2pt]
\textsc{backpatch}(L,t) &:\; \forall\, i \in L,\; q_i.\mathit{result} \leftarrow t \label{eq:backpatch}
\end{align}
\textsc{makelist} allocates a single-element list; \textsc{merge} concatenates two lists via pointer chaining in $O(1)$ amortised time; and \textsc{backpatch} iterates over every index in~$L$, writing the now-known target~$t$ into the result field.

\subsection{Semantic Attributes}
Grammar symbols carry structured semantic values via Bison's \texttt{\%union}:
\begin{itemize}[leftmargin=*]
\item \textbf{Expressions} ($E$): $\langle \mathit{name},\, \mathit{type},\, \mathit{is\_const},\, \mathit{val}\rangle$, supporting constant propagation.
\item \textbf{Boolean conditions} ($B$): $\langle \mathit{truelist},\, \mathit{falselist}\rangle$---lists of quads awaiting True/False branch targets, enabling short-circuit evaluation without Boolean flags.
\item \textbf{Statements} ($S$, $L$): $\langle \mathit{nextlist}\rangle$---quads whose exit targets are unresolved.
\end{itemize}

\subsection{Marker Non-Terminals}
Because LALR(1) parsers execute semantic actions only upon rule reduction, we inject $\varepsilon$-productions to capture the instruction counter at intermediate grammar positions:
\begin{align}
M &\to \varepsilon \qquad \{\; M.\mathit{quad} \leftarrow \mathit{nextquad}\;\} \label{eq:M} \\[2pt]
N &\to \varepsilon \qquad
\begin{cases}
N.\mathit{nextlist} \leftarrow \textsc{makelist}(\mathit{nextquad})\\
\textsc{emit}(\texttt{goto},\, -,\, -,\, \_)
\end{cases} \label{eq:N}
\end{align}
$M$ passively records the current index (an ``anchor''); $N$ additionally emits an unconditional jump with an unresolved target (a ``jump-and-record'' marker).

\section{Proposed Methods}

\subsection{Single-Pass Lexical Scoping via Dynamic Mangling}
\label{sec:scoping}

In C, a variable declared inside a nested block \texttt{\{~\ldots~\}} shadows any outer declaration of the same name. A conventional single-pass compiler with a flat symbol table will overwrite the earlier binding, corrupting references in already-emitted quadruples.

We maintain a \emph{scope stack} $\mathcal{S} = [s_0, s_1, \ldots, s_d]$ where $s_d$ is the current (innermost) scope. When a variable $x$ is declared at scope depth~$k$ and an active entry for~$x$ already exists at depth $j<k$, the new binding receives a mangled IR name:
\begin{equation}
\label{eq:mangle}
\mathit{IRName}(x, k) = x \,\|\, \text{``\_s''} \,\|\, k
\end{equation}
For example, given the following C fragment:
\begin{lstlisting}
int x = 10;              // scope 1: IR name = "x"
{
    int x = 100;          // scope 3: IR name = "x_s3"
    total += x;           // uses "x_s3"
}
total += x;               // uses "x" (outer)
\end{lstlisting}
the inner \texttt{x} is emitted as \texttt{x\_s3} throughout the quadruple stream while the outer \texttt{x} retains its original name. When the block closes, \texttt{scope\_exit()} marks all bindings at depth~$k$ as inactive ($\mathit{is\_active} \leftarrow \mathrm{false}$), restoring outer visibility in $O(1)$ time per symbol without deallocating the entries---their mangled names persist in the quad array.

Algorithm~\ref{alg:scope} summarises the scope-entry and scope-exit procedures.

\begin{algorithm}[t]
\caption{Scope-Aware Symbol Insertion}
\label{alg:scope}
\begin{algorithmic}[1]
\REQUIRE Variable name $x$, type $\tau$, current scope depth $k$
\STATE $e \leftarrow \textsc{Lookup}(x)$ \COMMENT{search active entries}
\IF{$e \neq \mathrm{null}$ \AND $e.\mathit{scope} = k$}
    \STATE \textbf{report} semantic error: redeclaration
\ELSIF{$e \neq \mathrm{null}$ \AND $e.\mathit{scope} < k$}
    \STATE $\mathit{name} \leftarrow x \,\|\, \text{``\_s''} \,\|\, k$ \COMMENT{mangle}
\ELSE
    \STATE $\mathit{name} \leftarrow x$
\ENDIF
\STATE Insert $\langle x, \mathit{name}, \tau, k, \mathrm{active}\rangle$ into table
\end{algorithmic}
\end{algorithm}

\subsection{Short-Circuit Boolean Evaluation}
\label{sec:boolean}

C's Boolean operators \texttt{\&\&} and \texttt{||} are \emph{short-circuiting}: the right operand is evaluated only when necessary. We implement this without Boolean flags by translating conditions directly into conditional jumps, using the $\mathit{truelist}$/$\mathit{falselist}$ attribute scheme.

For logical AND, the translation rule is:
\begin{align*}
B &\to B_1 \;\texttt{\&\&}\; M\; B_2 \\[3pt]
&\quad \textsc{backpatch}(B_1.\mathit{truelist},\; M.\mathit{quad}) \\
&\quad B.\mathit{truelist} \leftarrow B_2.\mathit{truelist} \\
&\quad B.\mathit{falselist} \leftarrow \textsc{merge}(B_1.\mathit{falselist},\; B_2.\mathit{falselist})
\end{align*}
If $B_1$ is false, the entire conjunction is false---$B_1$'s false jumps join the overall false list without evaluating $B_2$. If $B_1$ is true, control falls through to $B_2$ via the marker~$M$.

For logical OR:
\begin{align*}
B &\to B_1 \;\texttt{||}\; M\; B_2 \\[3pt]
&\quad \textsc{backpatch}(B_1.\mathit{falselist},\; M.\mathit{quad}) \\
&\quad B.\mathit{truelist} \leftarrow \textsc{merge}(B_1.\mathit{truelist},\; B_2.\mathit{truelist}) \\
&\quad B.\mathit{falselist} \leftarrow B_2.\mathit{falselist}
\end{align*}
This pure-jump scheme eliminates all Boolean temporaries and flag-test instructions.

\subsection{Dual-Marker Synchronisation for \texttt{for} Loops}
\label{sec:forloop}

The ANSI~C \texttt{for} statement presents an order mismatch between its grammatical structure and runtime execution:
\begin{center}
\begin{tabular}{@{}ll@{}}
\textbf{Parse order:} & \textit{init} $\to$ \textit{cond} $\to$ \textit{step} $\to$ \textit{body}\\
\textbf{Execution order:} & \textit{init} $\to$ \textit{cond} $\to$ \textit{body} $\to$ \textit{step} $\to$ \textit{cond}
\end{tabular}
\end{center}
The \textit{step} expression is parsed before the \textit{body}, yet must execute after it. Multi-pass compilers handle this by buffering the step in an AST node. We achieve the same effect in a single pass using two additional $\varepsilon$-markers, as illustrated in Fig.~\ref{fig:forloop}.

\noindent\textbf{Grammar production:}
\begin{align*}
S \to\; &\texttt{for}\;\texttt{(}\; S_{\mathrm{init}}\;\texttt{;}\; M_c\; B\;\texttt{;}\; N_{\mathrm{skip}} \\
        &M_s\; S_{\mathrm{step}}\; N_{\mathrm{back}}\;\texttt{)}\; M_b\; S_{\mathrm{body}}
\end{align*}

\noindent\textbf{Backpatch actions upon reduction:}
\begin{enumerate}[leftmargin=*]
\item $\textsc{backpatch}(N_{\mathrm{skip}}.\mathit{nextlist},\; M_b.\mathit{quad})$ --- the skip jump now lands on the body.
\item $\textsc{backpatch}(B.\mathit{truelist},\; M_b.\mathit{quad})$ --- the true branch enters the body.
\item $\textsc{backpatch}(S_{\mathrm{body}}.\mathit{nextlist},\; M_s.\mathit{quad})$ --- body fallthrough goes to the step.
\item $\textsc{backpatch}(\mathit{continuelist},\; M_s.\mathit{quad})$ --- \texttt{continue} jumps to the step.
\item $S.\mathit{nextlist} \leftarrow \textsc{merge}(B.\mathit{falselist},\; \mathit{breaklist})$ --- loop exits.
\end{enumerate}
The scheme requires only two extra \texttt{goto} instructions and zero auxiliary memory beyond the existing backpatch lists.

\subsection{Leader-Based CFG Synthesis with Typed Edges}
\label{sec:cfg}

After backpatching, the quadruple array is a flat sequence of instructions with resolved numerical targets but no explicit block structure. We partition it into basic blocks via the four-rule leader identification algorithm (Algorithm~\ref{alg:leader}).

\begin{algorithm}[t]
\caption{Leader Identification}
\label{alg:leader}
\begin{algorithmic}[1]
\REQUIRE Quadruple array $Q[0 \dots N{-}1]$
\ENSURE Boolean array $\mathit{isLeader}[0 \dots N{-}1]$
\STATE $\mathit{isLeader}[0] \leftarrow \mathrm{true}$ \COMMENT{Rule 1}
\FOR{$i = 0$ \TO $N-1$}
    \IF{$Q[i].\mathit{op} \in \{\texttt{if}, \texttt{goto}\}$}
        \STATE $t \leftarrow Q[i].\mathit{result}$
        \STATE $\mathit{isLeader}[t] \leftarrow \mathrm{true}$ \COMMENT{Rule 2}
        \IF{$i+1 < N$}
            \STATE $\mathit{isLeader}[i{+}1] \leftarrow \mathrm{true}$ \COMMENT{Rule 3}
        \ENDIF
    \ENDIF
    \IF{$Q[i].\mathit{op} \in \{\texttt{return}, \texttt{end}, \texttt{func\_end}\}$}
        \IF{$i+1 < N$}
            \STATE $\mathit{isLeader}[i{+}1] \leftarrow \mathrm{true}$ \COMMENT{Rule 4}
        \ENDIF
    \ENDIF
\ENDFOR
\end{algorithmic}
\end{algorithm}

Leaders define block boundaries $\{B_0, B_1, \ldots, B_K\}$. Inter-block edges are classified into four semantic types based on the terminating instruction of the predecessor block, as summarised in Table~\ref{tab:edges}.

\begin{table}[t]
\centering
\caption{CFG Edge Type Classification}
\label{tab:edges}
\footnotesize
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Edge Type} & \textbf{Trigger Condition} & \textbf{Semantics}\\
\midrule
\textsc{True}  & \texttt{if} branch taken     & Condition evaluated true\\
\textsc{False} & \texttt{if} branch not taken & Condition evaluated false\\
\textsc{Jump}  & Unconditional \texttt{goto}  & Always transfers control\\
\textsc{Fall}  & No branch at block end       & Sequential execution\\
\bottomrule
\end{tabular}
\end{table}

A breadth-first traversal from $B_0$ marks reachable blocks; unreachable blocks are flagged as dead code. The engine exports both Graphviz DOT specifications and self-contained interactive HTML visualisations rendered with Mermaid.js, colour-coding edges by their semantic type (green for True, red for False, blue for Jump, grey for Fallthrough).

\subsection{Four-Pass Optimiser with Address Remapping}
\label{sec:opt}

Post-backpatching optimisation on a linear quadruple array is hazardous: deleting or reordering instructions shifts indices, invalidating existing jump targets. Our optimiser executes four sequential passes:

\begin{enumerate}[leftmargin=*]
\item \textbf{Constant folding.} Evaluates compile-time arithmetic (e.g., $10+20 \to 30$), replacing binary operations on constant operands with a single assignment and eliminating the temporary variable.
\item \textbf{Jump chaining.} If $q_i = (\texttt{goto},\,-,\,-,\,j)$ and $q_j = (\texttt{goto},\,-,\,-,\,k)$, then $q_i.\mathit{result} \leftarrow k$, shortcutting the chain.
\item \textbf{Redundant jump elimination.} Removes any $\texttt{goto}~(i{+}1)$ that merely falls through to the next sequential instruction.
\item \textbf{Dead-code elimination with address remapping.} A BFS reachability pass over the CFG identifies dead quads. Live quads are compacted, and a displacement vector~$R$ is computed:
\begin{equation}
\label{eq:remap}
R[i] = i - \sum_{k=0}^{i-1}\mathbb{I}(q_k \text{ is dead})
\end{equation}
Every surviving jump target~$t$ is replaced by~$R[t]$:
\begin{equation}
\label{eq:apply_remap}
q_i.\mathit{result} \leftarrow R[q_i.\mathit{result}] \quad \forall\, q_i \text{ with } \mathit{op} \in \{\texttt{if}, \texttt{goto}\}
\end{equation}
This restores index consistency across the entire array in a single $O(N)$ pass.
\end{enumerate}

\section{Worked Example}
\label{sec:example}

To illustrate the backpatching pipeline end-to-end, consider the following C fragment:
\begin{lstlisting}
if (a < b && c > d) {
    x = 1;
} else {
    x = 2;
}
\end{lstlisting}

\noindent\textbf{Step 1: Translate \texttt{a < b}.} The relational expression emits two quads:
\begin{lstlisting}[style=quad]
0: if a < b goto _
1: goto _
\end{lstlisting}
yielding $B_1.\mathit{truelist} = \{0\}$, $B_1.\mathit{falselist} = \{1\}$.

\noindent\textbf{Step 2: Marker $M$ records $\mathit{nextquad} = 2$.}

\noindent\textbf{Step 3: Reduce \texttt{\&\&}.} Apply:
$\textsc{backpatch}(B_1.\mathit{truelist}, 2)$,
so quad~0 becomes \texttt{if a < b goto 2}.

\noindent\textbf{Step 4: Translate \texttt{c > d}:}
\begin{lstlisting}[style=quad]
2: if c > d goto _
3: goto _
\end{lstlisting}
Overall: $B.\mathit{truelist} = \{2\}$, $B.\mathit{falselist} = \{1, 3\}$.

\noindent\textbf{Step 5: Then-block.} Marker $M_2$ records $\mathit{nextquad} = 4$.
$\textsc{backpatch}(\{2\}, 4)$. Emit \texttt{4: x = 1}. Marker~$N$ emits \texttt{5: goto \_}.

\noindent\textbf{Step 6: Else-block.} Marker $M_3$ records $\mathit{nextquad} = 6$.
$\textsc{backpatch}(\{1, 3\}, 6)$. Emit \texttt{6: x = 2}.

\noindent\textbf{Final resolved output:}
\begin{lstlisting}[style=quad]
0: if a < b goto 2
1: goto 6
2: if c > d goto 4
3: goto 6
4: x = 1
5: goto 7
6: x = 2
7: ...
\end{lstlisting}
No Boolean temporaries or flag variables appear---control flows purely through conditional and unconditional jumps, confirming the short-circuit translation.

\subsection{Loop Context Stack}
A \emph{loop context stack} isolates \texttt{break} and \texttt{continue} targets across arbitrarily nested loops and \texttt{switch} statements. Each context record stores a type tag (\texttt{CTX\_WHILE}, \texttt{CTX\_FOR}, \texttt{CTX\_DO\_WHILE}, or \texttt{CTX\_SWITCH}), a \emph{breaklist}, and a \emph{continuelist}. When the parser encounters a \texttt{break} statement, it appends a \texttt{goto \_} quad to the nearest enclosing context's breaklist (which may be a \texttt{switch}). For \texttt{continue}, the stack is searched for the nearest enclosing \emph{loop}, skipping any intervening \texttt{switch} contexts. If no enclosing loop or switch is found, a semantic error is reported. This design correctly handles the C~semantics where \texttt{break} exits both loops and switches, while \texttt{continue} only loops.

\subsection{Error Recovery}
Syntax error recovery uses Bison's built-in panic-mode mechanism:
\begin{center}
\texttt{L : L M S | S | L error `;\textquotesingle}
\end{center}
When a syntax error is encountered, the parser discards tokens until it finds a semicolon, reports the error with exact line and column coordinates, and resumes parsing. This allows the compiler to detect multiple syntax errors in a single run. Semantic errors (redeclaration, type mismatch, stray \texttt{break}/\texttt{continue}, undeclared variables in strict mode) are similarly reported without halting, with compilation proceeding to collect all diagnostics before the final gate in \texttt{main.c} decides whether to abort.

\subsection{Command-Line Interface}
The compiler supports multiple output modes via CLI flags: \texttt{-{}-quads} (quadruple table), \texttt{-{}-symtab} (scoped symbol table), \texttt{-{}-cfg} (CFG with DOT and HTML export), \texttt{-O} (run optimiser), \texttt{-{}-strict} (enable undeclared-variable errors), \texttt{-{}-json} (machine-readable output), and \texttt{-{}-all} (all outputs combined). This flexibility supports both interactive exploration and automated testing.

% IX.  CONCLUSION AND FUTURE WORK
% ============================================================
\section{Conclusion and Future Work}

We have presented a single-pass intermediate code generator that extends classical backpatching with four mechanisms---scope-preserving identifier mangling, dual-marker loop synchronisation, flow-typed CFG synthesis, and address-safe optimisation---enabling it to handle a realistic subset of~C without constructing an AST. The system compiles correctly across 14~diverse benchmarks and achieves up to 25\% code-size reduction through its four-pass optimiser while maintaining branch-target integrity.

Several directions for future work emerge. First, the quadruple stream could be lowered directly into LLVM~IR bitcode~\cite{llvm}, enabling access to LLVM's mature optimisation and code-generation infrastructure. Second, Static Single Assignment~(SSA) $\phi$-functions could be constructed directly from our flow-typed CFG using the algorithm of Braun et al.~\cite{braun2022} or classical dominance frontiers~\cite{cytron1991}, avoiding the traditional full-AST pass. Third, a WebAssembly binary backend~\cite{wasmhaas} would enable in-browser execution of compiled programs. Finally, extending the grammar to support arrays, pointers, and \texttt{struct} types would bring the system closer to full ANSI~C coverage.
