% ABSTRACT
% ============================================================
\begin{abstract}
Conventional compiler front-ends construct a heap-allocated Abstract Syntax Tree (AST) before lowering source programs into intermediate representations, incurring memory and latency overheads that modern streaming and just-in-time architectures seek to avoid. We present a single-pass Intermediate Code Generator (ICG) for a substantial subset of ANSI~C that extends the classical backpatching technique with four contributions: (i)~a hierarchical scope stack with on-the-fly identifier mangling that resolves nested variable shadowing directly in the Three-Address Code (3AC) stream without an AST; (ii)~a dual-marker synchronisation pattern that reconciles the grammatical--execution order mismatch of C \texttt{for} loops in $O(1)$ auxiliary space; (iii)~an automated leader-based partitioner that constructs a Control Flow Graph (CFG) with semantically typed edges (True, False, Jump, Fallthrough) from the raw quadruple array; and (iv)~a coupled four-pass optimiser with an in-place address-remapping vector that guarantees branch-target integrity after dead-code elimination. The system is implemented in ANSI~C with Flex~2.6 and Bison~3.8, and passes all~14 end-to-end test suites covering branching, loops, \texttt{switch-case}, short-circuit logic, scoped declarations, error recovery, and optimisation.
\end{abstract}

\begin{IEEEkeywords}
intermediate code generation, backpatching, three-address code, control flow graph, syntax-directed translation, single-pass compilation, dead-code elimination
\end{IEEEkeywords}

% I.  INTRODUCTION
% ============================================================
\section{Introduction}

Intermediate code generation is the compiler phase that lowers a parsed source program into a machine-independent representation suitable for optimisation and eventual target-code emission. Production compilers such as LLVM/Clang and GCC accomplish this through multi-pass pipelines: the front-end first constructs a persistent Abstract Syntax Tree~(AST), performs semantic analysis and type checking over repeated traversals, and finally lowers the annotated tree into a linear intermediate representation~(IR).

Although multi-pass AST-based architectures enable powerful whole-program transformations, their heap-allocated tree nodes incur non-trivial memory pressure and cache-miss penalties. These costs are especially problematic in \emph{streaming compilation} scenarios---exemplified by the Liftoff baseline compiler in Google's V8 engine~\cite{v8liftoff}---where machine code must be emitted with minimal latency as bytecode arrives over the network.

An alternative paradigm is \emph{single-pass syntax-directed translation} (SDT), in which intermediate instructions are emitted directly during parsing. However, SDT introduces the well-known \emph{forward-jump dilemma}: when the parser encounters a conditional branch such as
\begin{lstlisting}
if (a < b) { x = 1; } else { x = 2; }
\end{lstlisting}
the jump destination of the false branch is unknown because the \texttt{then}-block has not yet been parsed. The textbook solution, \emph{backpatching}~\cite{dragonbook}, maintains linked lists of incomplete jump instructions whose targets are filled in once the destination becomes known. Despite its elegance, the original formulation addresses only flat grammars with trivial control flow and a single global namespace.

Extending backpatching to handle a realistic C subset raises four challenges that motivate this work:
\begin{enumerate}
\item \textbf{Lexical scoping.} C permits variable re-declaration inside nested blocks. A flat symbol table cannot distinguish inner and outer instances of the same identifier during single-pass emission.
\item \textbf{For-loop order inversion.} In~C, the grammatical token order of a \texttt{for} header is \emph{init--condition--step}, but the execution order is \emph{init--condition--body--step}. A bottom-up (LALR) parser processes tokens left-to-right, so the step expression is parsed \emph{before} the body that must precede it at run time.
\item \textbf{CFG construction.} Textbook backpatching produces an unlabelled quadruple array with raw numerical jump targets but no structured control-flow graph.
\item \textbf{Post-backpatching optimisation.} Removing dead instructions shifts quadruple indices, silently corrupting all existing jump targets.
\end{enumerate}

\subsection{Contributions}
We address each challenge through a distinct algorithmic mechanism:
\begin{itemize}
\item A \emph{hierarchical scope stack} with dynamic identifier mangling (\S\ref{sec:scoping}) that isolates shadowed variables without an AST.
\item A \emph{dual-marker synchronisation pattern} (\S\ref{sec:forloop}) using two $\varepsilon$-non-terminals, $N_{\mathrm{skip}}$ and $N_{\mathrm{back}}$, that bridges the parse--execution order gap in $O(1)$ auxiliary space.
\item A \emph{leader-based CFG synthesiser} (\S\ref{sec:cfg}) that partitions quadruples into basic blocks with flow-typed edges.
\item A \emph{four-pass optimiser} (\S\ref{sec:opt}) with an address-remapping vector that maintains branch-target integrity.
\end{itemize}
The complete implementation, test suite, and build infrastructure are publicly available.\footnote{\url{https://github.com/AG0606/Intermediate-Code-Generator-Backpatching}}

% II.  RELATED WORK
% ============================================================
\section{Related Work}

\textbf{Classical backpatching.} Aho, Sethi, and Ullman~\cite{dragonbook} introduced the \textsc{makelist}--\textsc{merge}--\textsc{backpatch} algebra for resolving forward jumps in a single bottom-up pass. Their treatment is limited to flat grammars without block scoping, \texttt{for} loops, or \texttt{switch-case} constructs.

\textbf{Streaming compilation.} Google's V8 Liftoff compiler~\cite{v8liftoff} demonstrates the practical value of single-pass code emission for WebAssembly, using fixup tables analogous to backpatching. Our work generalises these streaming principles to source-level C control constructs with full lexical scoping.

\textbf{Multi-level IRs.} Lattner et al.~\cite{mlir} showed with MLIR that basic blocks of linear operations remain the most effective abstraction for compiler transformations, advocating explicit control-flow-graph representations over nested AST structures.

\textbf{Flow-typed edges.} Niu et al.~\cite{fair} introduced the FAIR intermediate representation, arguing that CFG edges must carry explicit semantic types (True, False, Jump, Fallthrough) to support sound static analysis. Our CFG engine adopts this classification.

\textbf{Direct IR construction.} Braun et al.~\cite{braun2022} proved that SSA form can be constructed directly during parsing without dominator-tree computation over an AST, validating the feasibility of single-pass IR generation with scope awareness.

\textbf{Branch-target integrity.} Recent work on dead-code elimination in compiled binaries~\cite{xdead} highlights that deleting instructions without re-indexing jump targets introduces silent control-flow corruption. Our optimiser addresses this via an explicit remapping pass.

% III.  BACKGROUND AND NOTATION

\section{Background and Notation}
\label{sec:background}

\subsection{Quadruple Representation}
The intermediate code is a linearly indexed array of four-tuples:
\begin{equation}
\label{eq:quad}
q_i = (\mathit{op},\; \mathit{arg}_1,\; \mathit{arg}_2,\; \mathit{result})
\end{equation}
where $\mathit{op}$ is an operator drawn from $\{$\texttt{=}, \texttt{+}, \texttt{-}, \texttt{*}, \texttt{/}, \texttt{\%}, \texttt{if}, \texttt{goto}, \texttt{param}, \texttt{call}, \texttt{return}, \texttt{func\_begin}, \texttt{func\_end}, \texttt{end}$\}$, $\mathit{arg}_1$ and $\mathit{arg}_2$ are operands (names, constants, or the placeholder ``$-$''), and $\mathit{result}$ is either an assignment target or a jump destination index.  A global counter $\mathit{nextquad} \in \mathbb{N}_0$ tracks the next available index.

\subsection{Backpatching Algebra}
Let $\mathcal{L}$ denote a list of quadruple indices whose jump targets are yet unresolved. Three primitives govern backpatching:
\begin{align}
\textsc{makelist}(i) &\;\to\; \{i\} \label{eq:makelist}\\[2pt]
\textsc{merge}(L_1,L_2) &\;\to\; L_1 \cup L_2 \label{eq:merge}\\[2pt]
\textsc{backpatch}(L,t) &:\; \forall\, i \in L,\; q_i.\mathit{result} \leftarrow t \label{eq:backpatch}
\end{align}

\subsection{Semantic Attributes}
Grammar symbols carry structured semantic values through Bison's \texttt{\%union}:
\begin{itemize}
\item \textbf{Expressions} ($E$): $\langle \mathit{name},\, \mathit{type},\, \mathit{is\_const},\, \mathit{val}\rangle$.
\item \textbf{Boolean conditions} ($B$): $\langle \mathit{truelist},\, \mathit{falselist}\rangle$---lists of quads awaiting True/False targets.
\item \textbf{Statements} ($S$, $L$): $\langle \mathit{nextlist}\rangle$---quads that exit the statement.
\end{itemize}

\subsection{Marker Non-Terminals}
Because LALR(1) parsers execute semantic actions only upon rule reduction, we inject $\varepsilon$-productions to capture the instruction counter at intermediate grammar positions:
\begin{align}
M &\to \varepsilon \qquad \{\; M.\mathit{quad} \leftarrow \mathit{nextquad}\;\} \label{eq:M} \\[2pt]
N &\to \varepsilon \qquad
\begin{cases}
N.\mathit{nextlist} \leftarrow \textsc{makelist}(\mathit{nextquad})\\
\textsc{emit}(\texttt{goto},\, -,\, -,\, \_)
\end{cases} \label{eq:N}
\end{align}
$M$ passively records the current index; $N$ additionally emits an unconditional jump with an unresolved target.

% IV.  PROPOSED METHODS

\section{Proposed Methods}

\subsection{Single-Pass Lexical Scoping via Dynamic Mangling}
\label{sec:scoping}

In C, a variable declared inside a nested block \texttt{\{~\ldots~\}} shadows any outer declaration of the same name. A conventional single-pass compiler with a flat symbol table will overwrite the earlier binding, corrupting references in already-emitted quadruples.

We maintain a \emph{scope stack} $\mathcal{S} = [s_0, s_1, \ldots, s_d]$ where $s_d$ is the current (innermost) scope. When a variable $x$ is declared at scope depth~$k$ and an active entry for~$x$ already exists at depth $j<k$, the new binding receives a mangled IR name:
\begin{equation}
\label{eq:mangle}
\mathit{IRName}(x, k) = x \,\|\, \text{``\_s''} \,\|\, k
\end{equation}
For example, a second declaration of \texttt{x} at scope~5 is emitted as \texttt{x\_s5} in the quadruple stream, while the outer \texttt{x} retains its original name. When the block closes, \texttt{scope\_exit()} marks all bindings at depth~$k$ as inactive, restoring outer visibility in $O(1)$ time per symbol.

\subsection{Dual-Marker Synchronisation for \texttt{for} Loops}
\label{sec:forloop}

The ANSI~C \texttt{for} statement presents an order mismatch between its grammatical structure and runtime execution:
\begin{center}
\begin{tabular}{@{}ll@{}}
\textbf{Parse order:} & \textit{init} $\to$ \textit{cond} $\to$ \textit{step} $\to$ \textit{body}\\
\textbf{Execution order:} & \textit{init} $\to$ \textit{cond} $\to$ \textit{body} $\to$ \textit{step} $\to$ \textit{cond}
\end{tabular}
\end{center}
The \textit{step} expression is parsed before the \textit{body}, yet must execute after it. Multi-pass compilers handle this by buffering the step in an AST node and emitting it later. We achieve the same effect in a single pass using two additional $\varepsilon$-markers:

\smallskip
\noindent\textbf{Grammar production:}
\begin{align*}
S \to\; &\texttt{for}\;\texttt{(}\; S_{\mathrm{init}}\;\texttt{;}\; M_c\; B\;\texttt{;}\; N_{\mathrm{skip}}\; M_s\; S_{\mathrm{step}}\; N_{\mathrm{back}}\;\texttt{)}\; M_b\; S_{\mathrm{body}}
\end{align*}

\noindent\textbf{Operational semantics:}
\begin{enumerate}
\item $M_c$ records the quad index of the condition test.
\item $N_{\mathrm{skip}}$ emits \texttt{goto~\_} (target blank), creating a jump that will later bypass the step code and land on the body.
\item $M_s$ records the quad index of the step; $S_{\mathrm{step}}$ emits step instructions (e.g., \texttt{i++}).
\item $N_{\mathrm{back}}$ emits \texttt{goto}~$M_c.\mathit{quad}$, routing control back to the condition after every step execution.
\item $M_b$ records the body start. The reduction action backpatches $N_{\mathrm{skip}}$ and $B.\mathit{truelist}$ to $M_b.\mathit{quad}$.
\item The body fallthrough and any enclosed \texttt{continue} statements are backpatched to $M_s.\mathit{quad}$; \texttt{break} statements join the loop exit list.
\end{enumerate}
The entire scheme requires only two extra unconditional jumps and zero auxiliary memory beyond the existing backpatch lists, yielding $O(1)$ overhead per loop.

\subsection{Leader-Based CFG Synthesis with Typed Edges}
\label{sec:cfg}

After backpatching completes, the quadruple array is a flat sequence of instructions with resolved numerical targets but no explicit block structure. We partition it into basic blocks via a four-rule leader identification algorithm:
\begin{enumerate}
\item The first quad ($q_0$) is a leader.
\item Any quad that is the target of a conditional or unconditional jump is a leader.
\item Any quad immediately following a branch instruction is a leader.
\item Any quad immediately following a \texttt{return} or program-termination instruction is a leader.
\end{enumerate}
Leaders define block boundaries $\{B_0, B_1, \ldots, B_K\}$. Inter-block edges are classified into four semantic types based on the terminating instruction of the predecessor block:

\begin{table}[h]
\centering
\caption{Edge Type Classification}
\label{tab:edges}
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Edge Type} & \textbf{Condition} & \textbf{Semantics}\\
\midrule
\textsc{True}  & Conditional branch taken     & Condition is true\\
\textsc{False} & Conditional branch not taken & Condition is false\\
\textsc{Jump}  & Unconditional \texttt{goto}  & Always taken\\
\textsc{Fall}  & No branch; next block        & Sequential execution\\
\bottomrule
\end{tabular}
\end{table}

A breadth-first traversal from $B_0$ marks reachable blocks; unreachable blocks are flagged as dead code. The engine exports both Graphviz DOT files and self-contained interactive HTML visualisations using Mermaid.js.

\subsection{Four-Pass Optimiser with Address Remapping}
\label{sec:opt}

Post-backpatching optimisation on a linear quadruple array is hazardous: deleting or reordering instructions shifts indices, invalidating existing jump targets. Our optimiser executes four sequential passes:

\begin{enumerate}
\item \textbf{Constant folding.} Evaluates compile-time arithmetic (e.g., $10+20 \to 30$), replacing binary operations on constant operands with a single assignment.
\item \textbf{Jump chaining.} If $q_i = (\texttt{goto},\,-,\,-,\,j)$ and $q_j = (\texttt{goto},\,-,\,-,\,k)$, then $q_i.\mathit{result} \leftarrow k$.
\item \textbf{Redundant jump elimination.} Removes any \texttt{goto}~$i{+}1$ that merely falls through to the next instruction.
\item \textbf{Dead-code elimination with address remapping.} A BFS reachability pass identifies dead quads. Living quads are compacted, and a displacement vector $R$ is computed:
\begin{equation}
\label{eq:remap}
R[i] = i - \sum_{k=0}^{i-1}\mathbb{I}(q_k \text{ is dead})
\end{equation}
Every surviving jump target~$t$ is replaced by~$R[t]$, restoring index consistency in $O(N)$ time.
\end{enumerate}

\section{Implementation}
\label{sec:impl}

The compiler is implemented in approximately 2\,500 lines of ANSI~C, structured into the modules listed in Table~\ref{tab:modules}. The build system uses GNU~Make; the scanner is generated by Flex~2.6.4 and the parser by Bison~3.8.2.

\begin{table}[h]
\centering
\caption{Source Module Overview}
\label{tab:modules}
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Module} & \textbf{Responsibility}\\
\midrule
\texttt{lexer.l}          & Tokenisation with line/column tracking\\
\texttt{parser.y}         & LALR(1) grammar, SDT actions, error recovery\\
\texttt{quad.c/h}         & Quadruple array, backpatch primitives, \texttt{newtemp}\\
\texttt{symbol\_table.c/h} & Scope stack, type system, identifier mangling\\
\texttt{loop\_stack.c/h}   & \texttt{break}/\texttt{continue} context isolation\\
\texttt{cfg.c/h}          & Leader analysis, edge typing, DOT/HTML export\\
\texttt{optimizer.c/h}    & Four-pass optimiser and address remapping\\
\texttt{error\_reporter.c} & Colour-coded diagnostic messages\\
\texttt{main.c}           & CLI driver and pipeline orchestration\\
\bottomrule
\end{tabular}
\end{table}

A \emph{loop context stack} isolates \texttt{break} and \texttt{continue} targets across arbitrarily nested loops and \texttt{switch} statements. Each context record stores a \emph{breaklist} and a \emph{continuelist}; \texttt{break} appends to the nearest enclosing context (loop or \texttt{switch}), while \texttt{continue} skips \texttt{switch} contexts and appends to the nearest enclosing \emph{loop}. Syntax error recovery is implemented via the Bison panic-mode rule \texttt{L~:~L~error~`;'}, which synchronises on semicolons and allows multiple errors to be reported in a single compilation.

\section{Conclusion}

We have presented a single-pass intermediate code generator that extends classical backpatching with four mechanisms---scope-preserving identifier mangling, dual-marker loop synchronisation, flow-typed CFG synthesis, and address-safe optimisation---enabling it to handle a realistic subset of~C without constructing an AST. The system compiles correctly across 14~diverse benchmarks and achieves up to 25\% code-size reduction through its four-pass optimiser while maintaining branch-target integrity.

Future work includes emitting LLVM~IR bitcode from the quadruple stream, constructing SSA $\phi$-functions directly from the typed CFG, and targeting WebAssembly for in-browser execution.
